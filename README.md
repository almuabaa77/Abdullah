# حلقات جامع الخير بآل سرحان

واجهة عربية وإنجليزية لإدارة الحفظ والمراجعة والحضور في حلقات التحفيظ. يستخدم التطبيق React وTypeScript وTailwind CSS، ويقدم الخادم واجهة API من خلال Cloudflare Worker. تُحفظ السجلات في D1، وتستخدم المعاينة المحلية SQLite.

## التشغيل

- تثبيت الاعتماديات عبر `npm ci`.
- تشغيل المعاينة عبر `npm run dev` والتحقق من الأنواع عبر `npm run check`.
- بناء حزمة Worker وملفات PWA عبر `npm run build`. نقطة الدخول هي `dist/server/index.js`.
- تطبيق `drizzle/0000_workspace.sql` على قاعدة D1 المربوطة باسم `DB`.

## الحسابات

يعرض النشر الخاص في Sites مساحة معاينة مستقلة لكل هوية مصادق عليها. تحتوي المعاينة على سجلات اصطناعية ويمكن تغيير عرض الحساب من صفحة «المزيد».

لتفعيل الحسابات الفعلية، فعّل تسجيل الدخول بالجوال في مشروع Firebase، وأضف نطاق النشر إلى نطاقات Firebase Authentication المصرح بها. اضبط قيمتي `FIREBASE_WEB_CONFIG` و`BOOTSTRAP_UID` في بيئة الخادم. يفتح التحقق عبر Firebase مساحة فعلية منفصلة، ويراجع أول مشرف طلبات التسجيل أو يعتمد أرقام الحسابات مسبقًا. يحتاج النشر الخاص إلى منح وصول Sites للمستخدمين المقصودين.

يسمح Firebase بخيارات تقييد البلدان المستهدفة وإرسال الرموز. تتولى Firebase التحقق من الرمز وحماية الإرسال على مستوى الخدمة. لم تُضبط مفاتيح Firebase في النشر الحالي.

## التخزين

يتحقق الخادم من نطاق سجلات كل دور. يستخدم تحديث البيانات رقم مراجعة مع إعادة المحاولة عند التحديث المتزامن ومفتاحًا لكل عملية لمنع التكرار. الإصدار الحالي يخزّن مساحة العمل في سجل D1 واحد، ويعيد جلب بيانات الواجهة كل عدة ثوانٍ أثناء فتح الصفحة. يمكن فصل الجداول عند توسيع عدد الحلقات والسجلات.

تم التحقق من أعداد آيات السور الـ114 باستخدام بيانات الفصول من Quran.com API. يمكن حفظ تقارير PDF من نافذة الطباعة، ويصدر زر Excel ملف XLSX.

## التشغيل على Hostinger

يدعم المشروع استضافة Node.js بإصدار 22 أو أحدث على خطة تتيح تطبيقات Node.js. اربط فرع `halaqat-al-khair` من مستودع `almuabaa77/Abdullah` بإعدادات Express في hPanel.

- عند الرفع من GitHub، استخدم `npm run build` للبناء و`start.cjs` لملف الدخول. يعمل `server.js` أيضًا، وأمر التشغيل هو `npm start`.
- للرفع اليدوي من قسم Node.js، أنشئ حزمة التشغيل باستخدام `npm run package:hostinger -- /path/to/halaqat.zip`. ارفع الملف المضغوط وحدد `start.cjs` في مجلد الجذر `./`. الحزمة تضم التطبيق مبنيًا، ويمكن تشغيل أمر البناء الافتراضي للتحقق من ملفاتها.
- اربط قاعدة MySQL مخصصة للتطبيق. استخدم `DATABASE_URL` أو القيم `DB_HOST` و`DB_PORT` و`DB_NAME` و`DB_USER` و`DB_PASSWORD`. عند ضبط الطريقتين، يقرأ التطبيق `DATABASE_URL` أولًا. أدخل كلمة مرور مستخدم MySQL وحدها في `DB_PASSWORD`. عند استخدام الرابط، استخدم ترميز URL للرموز الخاصة في كلمة المرور. ينشئ التطبيق جدول `halaqat_workspaces` عند بدء التشغيل ويتحقق من إمكانية قراءته.
- اضبط `FIREBASE_WEB_CONFIG` و`BOOTSTRAP_UID` في متغيرات تشغيل Hostinger. يستخدم تطبيق Hostinger تسجيل الدخول الفعلي عبر Firebase.
- بعد النشر افتح `/api/health` للتحقق من وصول الطلبات إلى التطبيق. يظهر `app: halaqat-al-khair` مع حالة قاعدة البيانات `database`. تشير `ready` إلى جاهزية التخزين و`not_configured` إلى نقص إعدادات MySQL أو خطأ في صيغتها و`unavailable` إلى تعذّر الاتصال أو تهيئة الجدول. تبدأ الصفحة الرئيسية وفحص الصحة قبل اكتمال الاتصال بقاعدة البيانات. نسخة Hostinger تخزّن بياناتها في MySQL، ونسخة Sites تخزّن بياناتها في D1.
- عند العطل، يعرض `databaseIssue` رمزًا موجزًا. يشير `password_is_example` إلى لصق رابط اتصال أو نص مثال في موضع كلمة المرور، و`access_denied` إلى رفض MySQL تسجيل الدخول، و`connection_refused` إلى عدم قبول الاتصال على المضيف والمنفذ المحددين، و`permissions_denied` أو `schema_error` إلى مشكلة في الصلاحيات أو بنية الجدول. لا يعرض الفحص بيانات الاتصال.

## جلسات التسميع عبر Agora

يسمح قسم **جلسات التسميع والاجتماعات** في لوحة الإدارة بإنشاء جلسة حلقة أو تسميع خاص أو اجتماع إداري أو عاجل. يظهر التقويم في **المزيد ← جلسات التسميع** وفي تبويب **المكالمات**. يستطيع المحفّظ فتح جلسته وتوثيق التسميع في السجل الحالي، وتفعيل الجدولة من قبله قرار إداري. يطلب الطالب الدخول ثم يقبله المحفّظ، ويستطيع رفع اليد. تشغيل الميكروفون والكاميرا قرار صريح من المستخدم.

### إعداد الإنتاج

تُضاف القيم التالية من صفحة متغيرات بيئة تطبيق Node.js في Hostinger. تُحفظ الأسرار على الخادم فقط:

- `AGORA_APP_ID` معرّف المشروع العام. يوجد معرّف افتراضي للمنصة ويمكن تجاوزه لكل بيئة.
- `AGORA_APP_CERTIFICATE` شهادة المشروع السارية.
- `AGORA_CUSTOMER_ID` و`AGORA_CUSTOMER_SECRET` بيانات اعتماد REST للمشروع، وتُستخدم لإجراءات الفصل وفحص أعضاء القناة.
- `AGORA_COHOST_AUTH_ENABLED=true` بعد تفعيل Co-host token authentication فعليًا في Agora Console. تحقّق أيضًا من تفعيل مصادقة App Certificate في المشروع.

بعد حفظ المتغيرات وإعادة تشغيل التطبيق، يفيد `/api/health` بحالة الإعداد في `lessonRtcConfigured`. تشير القيمة `true` إلى اكتمال المتغيرات وتأكيد الإعداد المدخل، ويتحقق اختبار مستقل من قبول Agora للرموز وسريان صلاحياتها. جرّب أولًا جلسة خاصة بحسابي اختبار. استخدم حسابًا ثالثًا لاختبار حجب الدخول قبل الموافقة، ثم تحقق من أن طلب نشر الفيديو يُرفض في جلسة صوتية، ومن فصل UID قديم بعد الاستبعاد. يتحقق الخادم من العضوية في كل إصدار ويوقّع رقم المستخدم والقناة والصلاحية والمدة. عند سحب الصلاحية يغيّر رقم الجلسة للمشارك ويطلب فصل رقم الاتصال السابق عبر REST، ويؤخّر إصدار الرموز الجديدة حتى ينجح طلب الفصل أو يبلغ الرمز السابق حد انتهاء صلاحيته. يُحمّل SDK عند طلب دخول الوسائط.

### التخزين والتشغيل

تُضاف الحقول الاختيارية `lessons` و`lessonSeries` و`lessonRestrictions` إلى وثيقة مساحة العمل الحالية في MySQL. لا يوجد تغيير في أعمدة الجداول أو البيانات التعليمية السابقة. يستخدم الحفظ رقم المراجعة نفسه لتفادي تعارض الموافقات، وتستعيد المهام المواعيد والتذكيرات والفصل المطلوب من الوثيقة عند إعادة التشغيل. العودة للإصدار السابق تبقي الحقول في MySQL ما لم تُسترجع نسخة قديمة من قاعدة البيانات. يُنصح بالتسجيل بحسابات اختبار عند التحقق من الإصدار الجديد.

ينشر مؤقّت خادمي التذكيرات من الحالة المحفوظة، ويجهّز نافذة المواعيد المتكررة حتى 45 يومًا مقدمًا. تعمل المهام ما دام تطبيق Node.js يعمل. معدّل فحص حضور الوسائط يعتمد على طلبات Agora REST؛ الفترات تقديرية من وقت أول وآخر رصد ولا تُحوّل إلى تسميع مكتمل. التقويم يعرض مدة الجلسة والتنبيهات للمخوّلين. يمكن تنزيل فترات الحضور من تفاصيل الجلسة. خدمة SMS الخارجية والتسجيل وتقدير تكلفة خطة Agora خارج هذا الإصدار.

### التحقق

يشغّل `npm run test:lessons` اختبارات النظام والسياسات والرموز المحلية، بما فيها سعة قبول 24 حسابًا وعدم تكرار التذكير. هذا اختبار سعة منطقية على بيانات اصطناعية. اختبار 24 مشاركًا متصلًا فعليًا لمدة ساعتين واختبارات Safari على iPhone وشبكات الجوال تتطلب مشروع Agora مفعّلًا، واتصالًا فعليًا وتجهيز بيئة اختبار. لا تستند نتائج التشفير المحلي أو اختبار المتصفح دون الوسائط إلى مزود RTC حي.
